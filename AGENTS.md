# Repository guidance

This repository is an early-stage project. Read `docs/architecture.md`, the relevant decision records, and any applicable proposal before changing product responsibilities. Preserve existing owner decisions, and identify and escalate unresolved product or owner decisions rather than silently resolving them. `docs/architecture.md` is the canonical architecture contract; discussion and implementation materials do not amend it.

The Proposal is an intermediate artifact for review. It does not make or adopt an architecture decision, and a document's status label does not authenticate approval. Only the authorized owner can adopt a decision through the project's agreed process. For an existing consumer canonical authority, commit the exact Proposal at a repository path chosen under that consumer's conventions before the owner outcome for new decisions; decision 0006 permits only the narrowly bounded recovery of a valid prior-process pre-Git `Adopt` with durable exact-content evidence, identical bytes, repository authorization, required precommit reviews, and verified later Git binding. A later commit adds Git identity to already-identified content; it is not the revision the owner reviewed and is not a new outcome. After a qualifying outcome and binding, integrate only the adopted content on that same branch and hand off the reviewed, PR-ready repository change. The consumer owns PR creation, merge, Gatekeeper selection, and activation. A Gatekeeper-compatible Authority Set is an optional interoperability export, including when the consumer cannot select canonical authority directly; preserve the existing package integrity checks. Do not infer adoption, canonical targets, or normative wording. Report a missing/inaccessible target as a concrete blocker and route meaning-changing conflicts to the authorized owner.

Keep changes focused, preserve source attribution and third-party license notices, and describe what was reviewed when proposing a change. Do not claim validation, support guarantees, or release readiness unless the project has established evidence for those claims.
