# Contributing

Thanks for helping improve this project. ADA is an early-stage decision-authoring aid. A Proposal is for review; it does not adopt an architecture decision. An explicit owner outcome and the bounded finalization rules in [`docs/architecture.md`](docs/architecture.md) govern any Authority Set output.

## Before contributing

- Check the [open issues](https://github.com/flair-agency/architecture-decision-authoring/issues) and [project milestones](https://github.com/flair-agency/architecture-decision-authoring/milestones) for context.
- For substantial work, open or join an issue first and define one reviewable outcome with observable acceptance and verification criteria.
- Keep assumptions, unknowns, and unresolved owner decisions explicit. Consumer architecture and policy remain with their authorized owners.
- Preserve attribution and license information for third-party material; the original license continues to apply.

## Proposing changes

Use a pull request to state its outcome, issue coverage, verification, remaining work, and authority/assurance impact. Preserve the shared headings in the PR template for web and CLI/API-created pull requests, along with its third-party material notice. A partial implementation must identify uncovered issue criteria and must not close the issue. See the [Issue and pull request workflow](docs/issue-pr-workflow.md) for the project process.

Review, merge, or a status label does not imply that an architecture decision has been adopted. Adoption belongs to the authorized owner and follows the project's recorded decision process. Please follow the [Code of Conduct](CODE_OF_CONDUCT.md). There is no service-level agreement or guaranteed response time for issues or pull requests.
